# Обзор движка (src/worker)

Дата: 2026-11-09. База: коммит 4b25e03 (форк emamalet/Orca-git-log-panel 0.1.6).

## Базовый прогон

- `orca plugin test . --json` — exit 0, все тесты зелёные.
- `orca plugin types .` + `npx -y -p typescript@5 tsc -p . --noEmit` — база: 43 строки лога, 40 ошибок типов (exit 2). Почти все — отсутствие `@types/node` (`node:*`, `process`, `Buffer`) и производные неявные `any`; плюс `src/ui/diff.ts:206` (`findLastIndex`, нужен `lib: es2023`) и `src/worker/git.test.ts:227-239` (обращение к полям `PatchResult` без сужения по `ok`). Это база: новые задачи не должны её увеличивать.

## Находки по чтению воркера

Проверено: `git` вызывается только через `createGit` (`execFile`, без `shell: true`, без склейки строк в команду); у всех команд есть таймаут (по умолчанию 60 с, `cherry-pick`/`revert`/`rebase` — 120 с); хеши от фрейма проверяются `^[0-9a-f]{40}$` во всех действиях, `file.diff`, `patch.create`; имена веток и тегов проходят `check-ref-format`; `--`/`:(literal)` стоят там, где нужны; `repo.watch` не плодит наблюдателей (один на корень, запись в `Map` до завершения запуска). Уязвимостей, ведущих к выполнению команд, не найдено. Ниже — замечания; п. 3 — подтверждённая ошибка при нестандартном `gitPath`, исправлена (с регрессионным тестом); остальные не ошибки в обычном сценарии и не менялись (движок меняем минимально).

1. `src/worker/main.ts:36` (`gitFor`) — принимает любой абсолютный путь, являющийся корнем git-репозитория на диске, а не только корни, ранее выданные `repo.resolve`. Грозит: код фрейма (доверенный, свой) может читать и менять любой репозиторий пользователя. Решение: оставить, фреймы плагина — доверенный код; ограничивать список корней стоит только вместе с поддержкой нескольких репозиториев.
2. `src/worker/patch.ts:38` — путь сохранения патча берётся через `resolve(root, path)`; абсолютный путь или `..` выводят запись за пределы репозитория, `overwrite` перезаписывает существующий файл. Грозит: запись в произвольный файл по пути, который человек сам ввёл в диалоге. Оставлено как функция (сохранение патча вне репозитория), риск только при скомпрометированном фрейме.
3. `src/worker/rebase.ts:112` — в `exec`-строку todo был зашит `git`, а не путь из настройки `gitPath`. Грозило: при нестандартном `gitPath` (git вне `PATH`) каждый squash/reword завершался ошибкой и откатывался (`rebase --abort`), данные не терялись. Исправлено, коммит 802326f: путь доступен как `Git.gitPath` и передаётся в `buildTodo` (с `shQuote`); регрессионный тест в `src/worker/git.test.ts`. Предложить issue в апстрим.
4. `src/worker/log.ts:74` — пути фильтра подставляются после `--` как есть, без `:(literal)` (в отличие от `diff.ts`). Грозит: путь с `:(…)` или глобом трактуется как pathspec; только чтение. Возможно, это нужно для фильтра по маске; оставлено.
5. `src/worker/log.ts:165` (`readDetails`) — аргумент проверяется `assertRevision` (не начинается с `-`, без спецсимволов), а не регэкспом 40 hex. Безопасно (после него стоит `--`), но шире, чем у остальных запросов. Не менялось.
6. `src/worker/log.ts:68-69` — `since`/`until` не проверяются на число; не-число даёт `RangeError: Invalid time value`, который доходит до фрейма как ошибка запроса. Не ломает, только текст ошибки.
7. `src/worker/watch.ts:30-34` — наблюдение рекурсивное по всему `.git` (включая `objects`), фильтр применяется уже при событии. Расход: порядка сотни-двух наблюдателей inotify на большом репозитории с упакованными объектами; для репозитория с множеством свободных объектов число вырастет. Лимита на Linux хватает; сужение до `refs`, `HEAD` и `worktrees` — возможная оптимизация.
8. `src/worker/main.ts:80` — если запуск наблюдателя упал, `null` кэшируется в `watchers` навсегда (повтора нет), панель обновляется только по фокусу. Редкий случай.

Итог: исправлена одна ошибка (п. 3); в апстрим стоит предложить issue по ней (и, при желании, по п. 7). Issue не публиковались — решает пользователь.
