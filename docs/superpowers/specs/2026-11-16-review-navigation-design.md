## Зачем

Пользователь ведёт ревью коммитов заметками-обсуждениями, как в Azure DevOps, и упёрся в четыре вещи:

1. **Ошибка.** В списке «Заметки» вкладки Diff клик по заметке, написанной в другом коммите, открывает её файл в коммите, который вкладка показывает сейчас, — там заметки нет. Если в нём нет такого файла, клик ничего не делает. Причина (проверено по коду): `src/ui/notes.ts:841` ищет файл заметки среди файлов вкладки только по пути, коммит заметки не учитывается; без файла строка неактивна (`:848`).
2. **Кнопки ревью теряются.** «Заметки (N)» и «Отправить агенту» — те же серые `.tool`, что и семь кнопок навигации и вида; ярче всего в шапке — переключатель «Рядом». Действия в карточке — серые значки без подписей.
3. **Нет карты файла.** В режиме «Весь файл» не видно, где в длинном файле изменения и заметки. Полосу изменений пользователь уже просил (бэклог, п. 14); теперь к ней добавляются заметки.
4. **Заметки не видны в «Файлах».** В Azure обсуждения стоят строками под своим файлом в дереве файлов pull request'а; здесь, чтобы найти заметки, надо открыть каждый файл.

## Цели

1. Клик по любой заметке в списке «Заметки» показывает её карточку в диффе, где она написана, — из любого коммита, который сейчас во вкладке.
2. Кнопки ревью видны сразу: своя группа в шапке, отправка — главная кнопка, у действий карточки подписи.
3. В режиме «Весь файл» у правого края — узкая карта всего файла с изменениями и заметками; клик по метке ведёт к месту.
4. В секции «Файлы» панели под каждым файлом — строки его заметок; клик открывает файл и прокручивает к карточке.

## Не цели

- «Смотреть все» — все файлы выделения одной прокруткой (этап 2 из `2026-11-15-review-notes-design.md`); здесь не делается.
- Карта в сокращённом виде (только изменённые куски).
- Сворачивание заметок под файлом в дереве, свои клавиши для строк заметок, фильтр «только файлы с заметками».
- Переделка остальных кнопок списка «Заметки» («Удалить все», скилы) и меню «Отправить → Этот файл» (оно по-прежнему считает заметки файла по пути).
- Заметки в счётчиках папок и в сводке секции «Файлы».

## Анти-цели

- Переход к заметке меняет выделение в панели, хотя заметка видна в том, что уже выделено.
- Жёлтый цвет для выделения кнопок: в плагине он значит «предупреждение» (`.notes-warn`).
- Метки карты расходятся с кодом после переноса строк, раскрытия карточки или загрузки картинки.
- Под файлом показана заметка, которой нет в его диффе (и наоборот).

## Подходы

**1. Куда ведёт клик по заметке.** а) Вкладка открывает коммит заметки, а панель, если открыта, выделяет этот коммит в «Коммитах» — **выбрано пользователем**: файлы в панели и переходы ←/→ во вкладке про один и тот же коммит. б) Меняется только вкладка — отвергнуто: панель показывала бы другие файлы, чем вкладка.

**Какой коммит открыть.** Нужен коммит, чей собственный дифф (с первым родителем) меняет содержимое заметки на её стороне: тогда вкладка покажет карточку. У заметки есть `rev` (`notes.ts:378`): новая сторона — `to` файла выделения, старая — родитель первого коммита выделения, менявшего файл. i) Открыть `rev` (новая сторона) или ребёнка `rev`, меняющего путь (старая) — отвергнуто после проверки: если крайний коммит выделения только переименовал файл или сменил права, его дифф пустой и карточки нет; слияние `-s ours` проходит такой фильтр, не меняя файл. ii) Искать по содержимому: `git log --find-object=<blob>` от `rev`, с проверкой пары blob'ов — **выбрано (решение исполнителя)**: одна команда для обеих сторон, работает и для уже сохранённых заметок, без новых полей. iii) Новое поле якоря с коммитом — отвергнуто: только для новых заметок, и у переименования та же беда, что в i.

**2. Кнопки.** A — своя группа справа, отправка залита основным цветом Орки — **выбрано пользователем**. B — синяя плашка ревью, отвергнуто. C — отдельная строка ревью под шапкой, отвергнуто (съедает высоту). Макеты — в разговоре 2026-11-16.

**3. Карта.** а) Изменения и заметки, только «Весь файл» — **выбрано пользователем**, ширина около 5 px. б) Только заметки; в) и в сокращённом виде — отвергнуто. Позиции меток: по номеру строки — отвергнуто (строки разной высоты: перенос, карточки, картинки); по измерению DOM — **выбрано**. Место: поверх полосы прокрутки — отвергнуто (метки закрывали бы её дорожку от кликов); отдельная полоса справа от полосы прокрутки — **выбрано**.

**4. Заметки в «Файлах».** Строки под файлом, решённые бледные и последними — **выбрано пользователем** (4а). Сворачиваемый узел файла — отвергнуто: клавиши дерева (`dom.ts:45`) нажимают строку, а нажатие строки файла открывает дифф. Данные: тот же `notes.list`, что у вкладки, — **выбрано**; отдельный лёгкий запрос — не нужен, пока список укладывается в свой предел.

## Общее: blob'ы в файлах выделения

`SelectionFile` получает `oldBlob?` и `newBlob?` — полные id содержимого сторон. Нужны вкладке (шаг 1 перехода) и панели (п. 4).

- Worker берёт их там же, где сейчас статус: в `src/worker/selection.ts` оба вызова (`git log ... --name-status` и `git diff --name-status ... from to`) переходят на `--raw --no-abbrev` (проверено на git 2.56.0: `:100644 100644 <old40> <new40> R079\0a.txt\0b.txt\0`; id из одних нулей — стороны нет, поле не ставится). Парсер `--raw` — свой; `parseNameStatus` в `log.ts` остаётся для подробностей коммита.
- Это те же blob'ы, что `range.diff` даёт в `FileDiff` (проверено на git 2.56.0 для M, A, D, R с изменениями), кроме двух случаев: чистое переименование или смена прав — `--raw` даёт два равных id, а у диффа их нет; смена типа (`T`, файл ↔ симлинк) — git печатает два патча, `diff.ts` берёт первый `index`, и `newBlob` у диффа нет. Правило: **у файла с `oldBlob === newBlob` или со статусом `T` заметок нет** — ни под ним в дереве, ни во вкладке.
- Предел ответа фрейму — 1 МиБ (`worker/notes.ts:294`; в бандле Орки 2026-11-15 — проверка «answered with more than 1 MiB»). Поля добавляют 106 байт на файл. Окно вкладки в 2000 файлов уже сейчас не влезает при длинных переименованных путях (2000 × 200 символов с `oldPath` ≈ 1 072 КБ): **окно ограничивается байтами** — не больше 900 000 байт JSON вокруг выбранного файла, как список заметок (`notes.ts:294`), а не числом файлов.
- Ответ `selection.files` панели окна не имеет: с blob'ами выделение, на котором секция «Файлы» получает отказ Орки, уменьшается примерно с 6 100 до 3 800 файлов (пути по 50 символов). Принято как известный предел (`shortcut:` в коде): разбиение «Файлов» на страницы — отдельная задача.

## Общее: вкладка Diff в хранилище плагина

Выделение вкладки Diff, её текущий файл, `open` и `reveal` хранятся в хранилище плагина под ключом `diff:<sha256 root>` (`{ root, hashes, path, to, open, reveal? }`; `src/worker/notes.ts`, `diffKey`): Орка останавливает простаивающий worker и запускает новый по следующему запросу, и новый worker по `diff.state` строит файлы заново, как `diff.open`, и показывает их вместо заглушки; так же `diff.index` и `diff.focus`, если вкладка шагнула или её позвали раньше, чем она прочитала состояние у нового worker'а. Причина найдена 2026-11-16: состояние было только в памяти worker'а, живой `diff.state` давал `null` при открытой вкладке. Коммиты выделения пропали или значение не проходит проверку — заглушка и строка в `orca.log`. Ограничение: если файлы выделения не помещаются в окно 900 000 байт, новый worker строит окно вокруг сохранённого файла, и оно может начаться не там, где окно вкладки, — тогда шаг такой вкладки запишет другой файл; лечится хранением начала окна, если это встретится.

## 1. Переход к заметке

Клик (или Enter) по строке списка «Заметки» вкладки:

1. **Заметка видна в этой вкладке** — среди файлов вкладки есть файл, у которого blob стороны заметки равен её `blob` (текущий файл проверяется первым): как сейчас — показать этот файл и прокрутить к карточке, а если её строки вне изменённых кусков — включить «Весь файл» (`notes.ts:866-877`). Выделение в панели не меняется.
2. **Иначе — коммит заметки.** Вкладка просит worker открыть заметку (новый запрос, например `notes.open { root, id }` → `{ ok, reason? }`). Worker:
   - берёт заметку из хранилища и находит её коммит `C` — коммит, чей дифф с первым родителем меняет содержимое заметки на её стороне: `git log -M --diff-merges=first-parent --raw --no-abbrev -z --find-object=<blob> --format=%H <ревизии>`, где для новой стороны ревизии — `<rev>` (предки и сам `rev`, новые первыми, с ограничением числа, например `-n 50`), для старой — `--ancestry-path HEAD ^<rev>`, а без находки — `--ancestry-path --branches --remotes --tags ^<rev>` (потомки `rev`; без `--ancestry-path` `X ^<rev>` даёт и коммиты ветки, отошедшей до `rev`, и её более старая правка того же содержимого бралась бы как самая старая — найдено финальной проверкой 2026-11-16). Из найденных берётся коммит, у которого в выводе `--raw` есть пара с id заметки на её стороне и другим id на другой (новая: `new = blob`, `old ≠ blob`; старая: `old = blob`, `new ≠ blob`): `--find-object` сам выдаёт и чистые переименования (`R100`, оба id равны) — они отбрасываются. Для новой стороны — первый такой (обычно сам `rev`), для старой — самый старый (ближайший к `rev`). Проверено на git 2.56.0 во временном репозитории: переименование на краю выделения (новая сторона — находится коммит, где содержимое написано под старым именем; старая — коммит, где оно изменено после переименования), слияние `-s ours` (не выдаётся: его дифф с первым родителем пуст), правка на побочной ветке после слияния (находится), более старая правка того же содержимого на ветке, отошедшей до `rev` (не берётся);
   - строит файлы выделения `[C]` (как `diff.open`) и находит файл заметки по blob стороны; если таких файлов несколько — тот, чей путь совпадает с путём заметки;
   - пишет состояние вкладки с id заметки (`DiffTabState.reveal?`), открывает вкладку и шлёт `diff.show`;
   - шлёт панелям новое событие (например `commit.reveal { root, hash: C, path }`): панель того же репозитория выделяет `C` в «Коммитах» тем же путём, что запрос из файла `reveal.json` (сначала история HEAD, иначе все ветки, иначе обычное «нет в журнале»), и подсвечивает файл, когда файлы выделения загрузятся. Панели нет на экране — событие теряется (не проверено, что Орка его не доставит), вкладка всё равно переключается.
3. **Вкладка с `reveal`** после монтирования ждёт и дифф, и заметки, затем прокручивает к карточке (с «Весь файл», если нужно) — без второго запроса диффа. Worker отдаёт `reveal` при каждом чтении `diff.state` вместе с id открытия `open` (12 hex, новый на каждый `diff.open` и `notes.open`), пока его не снимут `diff.index` или новое открытие без заметки. Вкладка прокручивает к заметке один раз на `open`: последний выполненный `open` она хранит в `localStorage` под ключом `git-log.revealed.<root>` и записывает его, когда передаёт `reveal` в вид. Поэтому прокрутку не повторяют ни новый `diff.show`, ни перезагрузка фрейма, и она не теряется, когда новая вкладка читает состояние дважды (при старте и по `diff.show`), а первый показ отменён вторым. Повторное чтение того же `open` вид не пересоздаёт: показ остаётся, и прокрутка, которая ждёт загрузки файла, не обрывается.
4. **Ошибки** — коммит не найден (содержимое заметки ни в одном коммите не меняется: объекты удалены после rebase и сборки мусора), в нём нет файла с этим blob — показываются строкой наверху списка «Заметки», как отказ изменения (`refused`). Строки списка всегда активны (убрать `disabled` и комментарий `notes.ts:845`).
5. Панель по событию не забирает фокус клавиатуры.
6. Новая команда git — новая строка в `docs/git-safety.md` (входы: `rev` и `blob` из хранилища заметок; проверки: оба — 40-hex, `rev` — коммит, ревизии и `--find-object` собираются только из них).

## 2. Кнопки ревью (вариант A)

- **Шапка вкладки.** Порядок справа: `[Рядом|Вместе] [Весь файл] | [Заметки (N)] [Отправить агенту (N)]` — группа ревью после черты и последней.
  - «Заметки»: кнопка с рамкой (outline по правилам плагинов: рамка `--orca-input`, фон `color-mix(--orca-input 30%)`), значок, подпись и счётчик-кружок незакрытых обсуждений. Предупреждение (`notes-warn`) — жёлтые рамка и текст; в светлой теме жёлтый темнее (как `.head-state .op`, `styles.css:287`).
  - «Отправить агенту»: залитая `--orca-primary` / `--orca-primary-foreground`, значок, видимая подпись и счётчик-кружок неотправленных. Нет неотправленных — кнопки нет, как сейчас.
- **Плавающая кнопка у выделения**: залитая основным цветом, значок и подпись «Заметка».
- **Карточка**: «Отправить снова» и «Решено» / «Открыть снова» — маленькие кнопки с рамкой (24 px, 12 px текст) со значком и подписью. «Удалить» остаётся значком с подтверждением вторым нажатием; «Изменить» у сообщения — значком.
- Цвета — только переменные Орки и уже заведённые цвета состояний (`orca-plugin-ui`); подписи — ключи i18n на английском и русском.

## 3. Карта файла

- Показывается только в режиме «Весь файл», когда у диффа есть строки; у бинарного, пустого и «нет изменений» диффа её нет.
- Полоса шириной 5 px справа от полосы прокрутки `.diff-body`, во всю её высоту; вся высота полосы — весь отрисованный файл. Монтируется рядом с `.diff-body`, не внутри: `render()` заменяет детей `body` (`diff.ts:229-259`). Для чтения с экрана скрыта (`aria-hidden`): к изменениям ведут F7 / Shift+F7, к заметкам — список.
- **Метки изменений**: блок — подряд идущие изменённые строки; только добавления — `--st-added`, только удаления — `--st-deleted`, и то и другое — `--st-modified` (цвета статусов файлов, как в WebStorm). Высота — высота блока в масштабе, не меньше 2 px.
- **Метки заметок**: от строки начала до строки конца заметки на её стороне, цвет подсветки заметки (`--state-wait`), поверх меток изменений, на всю ширину, не меньше 3 px; решённые — 40 % непрозрачности. Черновик новой заметки метки не получает.
- **Позиция** = смещение строки внутри `.diff-lines` / полная высота `.diff-lines` × высота полосы. Пересчёт после каждой отрисовки и при изменении размеров `.diff-body` и `.diff-lines` (`ResizeObserver`: перенос строк, раскрытие карточек, картинки, шрифт Орки), не чаще раза за кадр.
- **Клик** по метке прокручивает к началу блока или заметки так, чтобы оно встало в 40 px от верха, как F7 (`diff.ts:286-293`). Подсказка (`title`): «Добавлено / Изменено / Удалено, строки a–b» или «Заметка, строки a–b: <начало первого сообщения>».
- Один вид полосы и для «Рядом», и для «Вместе»: позиции берутся из DOM.
- Обрезанный дифф (больше 20 000 строк) — карта покрывает отрисованную часть.

## 4. Заметки в «Файлах»

- Панель загружает заметки своего репозитория тем же `notes.list` при открытии репозитория и при событии `notes.changed` с его корнем (сейчас панель их не загружает и это событие не слушает). Ошибка загрузки — строк заметок нет, панель не ломается.
- **Какие заметки под файлом**: те, что вкладка показала бы в его диффе, — blob стороны заметки равен `oldBlob` / `newBlob` файла (как `notesOf`, `notemodel.ts:62`), у файла `oldBlob !== newBlob` и статус не `T`.
- **Строка заметки** — лист дерева на уровень глубже файла, сразу под ним: кружок состояния, номер первой строки (моноширинный, приглушённый), начало первого сообщения с многоточием. Подсказка — путь, строки, сторона, состояние и первое сообщение целиком.
  - Кружок: не отправлено — пустой приглушённый; отправлено, ответа нет — жёлтый (`--state-wait`); есть ответ агента — синий (`--state-info`); подтверждено или исправлено — зелёный (`--state-done`); решено — галочка, вся строка бледная.
  - Порядок: незакрытые по номеру строки, затем решённые по номеру строки.
- **Строка файла**: справа значок обсуждения и число незакрытых заметок; ноль — ничего.
- **Клик / Enter** по строке заметки открывает файл во вкладке (как клик по файлу, `diff.open`) с id заметки, и вкладка прокручивает к карточке, как в п. 1.3. Клавиши — как у листа дерева (`dom.ts`): ← к файлу, ↑↓ по строкам. Ключ строки (`data-key`) уникален и начинается с пути файла и `/`, чтобы фокус при исчезновении строки вернулся к файлу (`dom.ts:55`).
- Подсветка текущего файла (`diff.current`) не меняется; счётчики папок и сводка секции считают только файлы.

## Ограничения

- Только переменные Орки и цвета состояний из `styles.css` (`orca-plugin-ui`). Новые строки интерфейса — в `src/shared/i18n.ts` на английском и русском (`i18n.test.ts`).
- Тесты — `node:test` (`orca plugin test .`). Чистая логика (блоки изменений, сопоставление заметок с файлами, поиск коммита, парсер `--raw`) — в модулях с тестами; DOM-части проверяются стендом в headless Chromium.
- Некоторые исходники хранятся со смешанными концами строк (`src/worker/main.test.ts`, `src/ui/graph.test.ts`): после правки — `git diff --stat`.
- Тесты, сравнивающие `SelectionFile` целиком (`selection.test.ts`, `main.test.ts:207-219`), получают новые поля.
- Живая проверка в Орке — только с разрешения пользователя, одним заходом (у него в Орке работают агенты).
