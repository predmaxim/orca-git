# Ревью коммитов с заметками для агента и «Смотреть все» — дизайн

Дата: 2026-11-15. Статус: записан по просьбе пользователя («не выполнять сейчас, просто записать всё»). Что решено, пользователь одобрил в разговоре 2026-11-15. Перед планом осталось: выбрать подход (раздел «Подходы»), прогнать документ через проверку свежим агентом (builder check).

## Зачем

Пользователь смотрит выделенные коммиты во вкладке Diff и хочет оставлять агенту замечания прямо в коде, а потом одним нажатием отдать их агенту. В Orca это уже есть («notes for the AI»), и пользователь хочет **повторить Orca**: тогда не нужны свои настройки агента, а поддерживать проще. Отличия от Orca — только там, где Orca не устраивает:

- заметка цепляется к **выделенному тексту**, а не к строке;
- текст заметки — **markdown**;
- агент **отвечает** на каждую заметку.

Отличия потом можно предложить Orca pull request'ом.

## Цели

1. «Смотреть все»: все файлы выделенных коммитов одной прокруткой, как `CombinedDiffViewer` Orca, с правками плагина.
2. Заметки как в Orca, плюс привязка к выделенному тексту и markdown.
3. Отправка как в Orca: в открытого агента или в нового.
4. Задание агенту: в промпте ссылка на файл с заметками, а не сам файл. Скиллы проекта главнее. Если подходящего нет — свой стандартный скилл плагина. Агент по каждой заметке подтверждает или опровергает её ответом; подтверждённое исправляет.
5. Ответ агента виден под заметкой.

## Не цели

- Свои настройки модели и агента. Модель и вид запуска остаются за Orca; когда Orca даст это плагинам, плагин возьмёт (черновик issue — `docs/orca-issues.md`, пункт 3).
- Переписка в несколько раундов: на заметку — один ответ агента (моё решение, расширяемо).
- Общие заметки с Orca: API плагинов к заметкам Orca доступа не даёт.

## Анти-цели

- Заметки исчезают после отправки, как в Orca: тогда некуда показать ответ.
- Агент правит код, не сказав, согласен ли он с замечанием.
- Ответ агента исполняется как HTML во фрейме: markdown рисуется без сырого HTML.

## Как это сделано в Orca

Разведка по бандлу Orca 1.4.258 (`/tmp/orca-asar/x/out`, приложение не запускалось), 2026-11-15.

- **Заметка:** поля `id, worktreeId, filePath, source, selectedText?, startLine?, lineNumber, body, createdAt, updatedAt?, sentAt?, side: "modified"`. Привязка — строка или диапазон строк, только новая сторона. `selectedText` есть только у заметок в markdown-превью. Нет SHA коммита.
- **Хранение:** по workspace, в SQLite Orca (`profile-state.db`), переживает перезапуск.
- **Создание:** «+» в колонке номеров строк при наведении, протяжка по колонке выделяет диапазон; `Mod+Shift+A` (`editor.addReviewNote`) превращает выделение в целые строки. Редактор — textarea в view zone под строкой: Enter сохраняет, Shift+Enter — новая строка, Esc — отмена.
- **Текст:** обычный, markdown не рисуется. Правка снимает отметку «отправлено».
- **В диффе:** карточка под строкой: правка, удаление, кнопка «This note». В Source Control — список: строка или диапазон, метки MD/Diff и «Sent», Copy, Delete, «Copy all notes», «Clear notes for {path}», «Clear all notes».
- **Отправка** (`DiffNotesSendMenu`): что отправить («This file», «All unsent notes») и куда — открытые агенты (терминалы и чаты) или «New agent». У «New agent» тот же список, что у кнопки нового агента в полосе вкладок: найденные агенты плюс всегда `claude` и `codex`, каждый как чат или терминал; модель и effort — из настроек Orca.
- **Текст агенту:** блоки, разделённые пустой строкой, без вступления и без кода:
  ```
  File: <path>
  Line: N | Lines: a-b | Scope: file
  User comment: "<текст, экранированный>"
  ```
- **После отправки:** доставленные заметки удаляются (`clearDeliveredDiffComments`).
- **«Смотреть все»** (`CombinedDiffViewer`): вкладка со всеми файлами одной прокруткой; секции грузятся лениво, список виртуальный; Expand/Collapse All, Inline / Side by Side, перенос строк, пробелы; дерево файлов с фильтром, фильтром по расширению, «Viewed files»; поповер «AI notes» (Copy / Clear / Send). Заметки там работают.
- **API плагинов:** ничего для заметок и диффов.

## Решено

### «Смотреть все»

Режим вкладки Diff: все файлы текущего выделения коммитов одной прокруткой, повторяя `CombinedDiffViewer`: дерево файлов слева (фильтр, «Viewed»), Expand/Collapse All, Inline / Side by Side, ленивые секции. Палитры, шрифт и клавиши остаются плагина (настройка «Diff colors», F7, Alt+↑/↓).

### Заметка

- **Создание:** выделить текст в коде диффа, нажать «+» у выделения или `Ctrl+Shift+A`. Без выделения — как в Orca: строка или диапазон строк.
- **Редактор и карточка:** как в Orca (Enter сохраняет, Shift+Enter — новая строка, Esc — отмена); в карточке markdown отрисован; правка, удаление; правка снимает «отправлено».
- **Сторона:** старая или новая (Orca — только новая): выделить можно и удалённый код.
- **Хранение:** у плагина (Orca plugin storage, `storage:own`), по корню репозитория, переживает перезапуск.
- **Поля (моё предложение):** `id`, `root`, `hashes` (коммиты выделения), `path`, `oldPath?`, `side: old | new`, `start {line, col}`, `end {line, col}`, `quote` (выделенный текст), `body` (markdown), `createdAt`, `updatedAt?`, `sentAt?`, `reply? {verdict: confirmed | refuted, body, fixed, at}`.
- **Список:** счётчик в шапке диффа и поповер «AI notes» с Copy / Clear / Send, как в объединённом виде Orca (моё решение: панель Source Control плагину недоступна).

### Отправка

- В шапке диффа горит «Отправить агенту (N)», пока есть неотправленные заметки.
- Меню как в Orca: что отправить («Этот файл», «Все неотправленные») и куда:
  - открытый агент: агенты текущего worktree из `agents.list`, у которых есть терминал; текст уходит через `terminal.sendText`;
  - «Новый агент»: `agent.launch` (только терминал), список как у Orca — запущенные виды агентов плюс `claude` и `codex` (моё решение).
- Открытые **чаты** недоступны: плагин не может писать в чат (`agentSession.send` у Orca, у плагина только `terminal.sendText`, и только терминалы активного worktree). Пункт issue.
- Отправленная заметка остаётся с отметкой «отправлено» до ответа и после него; убирает её пользователь (Clear).
- Права для манифеста: `agent:read`, `terminal:send`, `agent:launch`, `storage:own` — обновление попросит одобрение заново.

### Задание агенту

- **Файл заметок:** worker пишет `.orca-git-log/review-<id>.md` в корне worktree (папка в `.git/info/exclude`, как якорь вкладки Diff). В нём по каждой заметке: блок Orca (`File:` / `Line(s):`), цитата выделенного кода, текст заметки, её `id`, и формат ответа.
- **Промпт** (лимит плагина — 4096 символов): ссылка на файл заметок, ссылка на скилл и куда писать ответы, а не сам файл. Черновик:

  > Review notes from the user: `<путь к файлу заметок>`. Work through every note: check it against the code, then confirm or refute it with a short reason, and fix the code for each confirmed note. Use this project's own skills first (`.claude/skills`, `.agents/skills`, `AGENTS.md`, `CLAUDE.md`); if none of them fits, follow `<путь к скиллу плагина>`. Write your answers to `<путь к файлу ответов>` in the format the notes file gives.

- **Свой стандартный скилл:** `skills/review-notes/SKILL.md` в плагине; агент получает ссылку на него в установленной копии плагина. Суть: прочитать заметки; по каждой проверить по коду (прочитать, при нужде запустить тесты); вердикт без поддакивания (как в superpowers `receiving-code-review`); подтверждённое исправить минимальной правкой; записать ответы; коротко отчитаться в чате.
- **Ответы:** агент пишет `.orca-git-log/review-<id>.answers.json` — `[{ id, verdict: "confirmed" | "refuted", reply: "<markdown>", fixed: true | false }]`. Worker замечает файл (уже следит за репозиторием) и кладёт ответ в заметку; под заметкой — ответ с меткой «подтверждено», «опровергнуто» или «исправлено».

«Ссылка» понята как путь к файлу в промпте вместо вставки самого текста. Если имелось в виду другое (URL), поправить здесь.

## Подходы — выбрать перед планом

**A. Достроить свою вкладку Diff** (HTML + highlight.js, как сейчас) по образцу интерфейса Orca. Markdown — небольшая библиотека в `src/vendor` (как highlight.js), без сырого HTML. Плюсы: умеренный объём, остаются палитры Orca/WebStorm, клавиши, подсветка слов, без тяжёлых зависимостей. Минусы: код не общий с Orca, PR в Orca — отдельная работа в их коде на Monaco. **Рекомендую.**

**B. Перенести вьюер Orca** (React + Monaco из `stablyai/orca`, MIT, «Copyright (c) 2026 Lovecast Inc.») в плагин. Плюсы: выглядит и ведёт себя как Orca один в один, правку с выделением почти как есть можно отдать в Orca PR'ом. Минусы: React и Monaco ESM (мегабайты) в `src/vendor` без сборки; Monaco во фрейме плагина нужен web worker — работает ли, не проверено; палитры WebStorm придётся заново сделать темами Monaco; свои клавиши и подсветку слов — переписать. Если выбирать B, сначала короткий пробный запуск Monaco во фрейме.

**Доставка:** только API плагинов (моё решение). Обход — вызывать из worker'а `orca agent launch --surface chat --model …` (CLI Orca это умеет) — обходит штатный механизм плагинов; только с явного разрешения пользователя.

## Риски

- **Rebase и amend** сдвигают код: в заметке хранятся SHA и цитата; если цитата не находится на месте, заметка помечается «устарела».
- **Агент не записал ответы:** заметка остаётся «отправлено, без ответа».
- **Безопасность:** ответ агента и заметки рисуются как markdown без HTML; ссылки — через `shell.openExternal`.
- **Новый агент** с видом, которого нет на машине (например `codex`), упадёт в терминале — как у Orca.

## Оставлено исполнителю

Раскладка поповера «AI notes», точный текст скилла плагина, формат файла заметок, как помечать «устарела», ключи i18n, тесты на привязку выделения и на разбор ответов.
