# Плагин «Git» для Орки — дизайн

Дата: 2026-11-09. Статус: одобрен пользователем 2026-11-09.

## Зачем

Пользователь привык работать с git в WebStorm, в окне Git Log. Встроенный в Орку source control и плагины git из каталога Орки его не устраивают. Нужен плагин для Орки, который повторяет окно Git Log из WebStorm в упрощённом виде. Главный сценарий — **ревью**: выбрать ветку (обычно HEAD), выделить несколько своих последних коммитов, пройти по изменённым файлам и прочитать дифф каждого.

Референс — скриншот окна Git Log в WebStorm. В git его нет: на нём данные рабочего репозитория пользователя; локальная копия — `.local/webstorm-reference.png` (папка исключена через `.git/info/exclude`). В WebStorm три секции: ветки, коммиты с графом, файлы выбранных коммитов. Клик по файлу открывает дифф в редакторе. В каждой секции есть полный набор действий git: поиск веток и коммитов; checkout, удаление и прочее для веток; reset, cherry-pick и прочее для коммитов.

«Упрощённо» значит: без кнопок настроек, консоли git и прочих мелочей WebStorm. Их можно добавлять потом, по мере надобности.

## Основа: форк `emamalet.git-log`

Решение пользователя: не писать с нуля, а форкнуть плагин Git Log (`github.com/emamalet/Orca-git-log-panel`, MIT, установлен у пользователя как `emamalet.git-log` 0.1.5). Из форка берём **движок**, проверяем его и доделываем, а интерфейс переделываем под вид WebStorm.

- PR в апстрим не отправляем: у автора своё видение (плагин повторяет аналогичный плагин для VS Code), его вид пользователю не нравится.
- Изменения апстрима время от времени просматриваем и переносим к себе: remote `upstream`, просмотр `git log ..upstream/main` и перенос нужного.
- Чтобы переносить было проще, движок (`src/worker/`, `src/shared/protocol.ts`) меняем как можно меньше: новое — новыми обработчиками и файлами, а не правкой старых.

Что такое движок (на момент форка, около 5,5 тыс. строк вместе с CSS):

- `src/worker/` — Node-воркер плагина (`execution: trusted-worker`). Запускает `git` через `execFile` без shell, пути передаёт как `:(literal)`. Читает лог страницами, ветки и теги, детали коммита, дифф одного файла коммита против первого родителя. Выполняет действия: checkout, new branch, tag, cherry-pick, revert, reset (soft/mixed/hard/keep), undo, squash, fixup, drop, reword, interactive rebase, create patch. Предупреждает о переписывании уже запушенных коммитов и даёт Undo. Следит за `.git` через `fs.watch` и сообщает интерфейсу `repo.changed`.
- `src/shared/protocol.ts` — типы запросов между интерфейсом и воркером (`repo.resolve`, `repo.refs`, `log.page`, `commit.details`, `file.diff`, `action.check`, `action.run`, `tab.open` и др.).
- `src/ui/` — интерфейс: одна HTML-страница (`panel.html` для сайдбара, `editor.html` для вкладки, общий `app.ts` с режимом `data-mode`), граф, дерево веток, фильтры, меню, диалоги, просмотр диффа. Его переделываем.

«Проверить движок» значит: прогнать его тесты (`orca plugin test`), прочитать воркер на предмет ошибок и опасных мест и проверить на реальных репозиториях пользователя, включая большой рабочий (путь — в локальной заметке `.local/notes.md`, в git не попадает).

## Ограничение Орки: вкладка через файл-якорь

У плагинов Орки нет API, чтобы открыть свою вкладку в редакторе без файла. Есть только `editor.open` (открыть файл рабочего пространства) и custom editor для типа файла. Поэтому плагин кладёт файл-якорь в корень рабочего пространства, которое держит репозиторий (сначала `.orca-git-log.gitlog` для вкладки «Git», после задачи 14c — `.orca-git-log.gitdiff` для вкладки «Diff») и дописывает его в `.git/info/exclude`, чтобы git его не видел. Открытие этого файла показывает вкладку плагина. Старые якоря `.orca-git-log.gitlog` в репозиториях, где вкладка «Git» открывалась, остаются скрытыми и ни на что не влияют; плагин их не удаляет.

По правилам пользователя это обход платформы. Пользователь согласился его оставить, потому что другого пути нет, и завести в Орке (`github.com/stablyai/orca`) issue на API «открыть вкладку плагина без файла». Issue — публичное действие: перед отправкой показать текст пользователю.

## Раскладка

Решение пользователя 2026-11-10: вкладки «Git» с полным видом нет. Плагин — это панель в сайдбаре и одна вкладка «Diff». Это ближе к WebStorm: лог — в панели, дифф — в редакторе. Прежний вариант (вкладка «Git», раскладка C1, макет `layout-mockup.html`) был реализован в задачах 5–12 и убран задачей 14c.

### Панель в правом сайдбаре — единственный вид плагина

Макет — `sidebar-details-mockup.html`, вариант «Б. Подробно» (выбор пользователя).

- Колонка из четырёх секций стопкой: **Ветки**, **Коммиты**, **Файлы**, **Описание**.
- Каждая секция сворачивается кликом по заголовку. Свёрнутая секция — одна строка с кратким итогом: у веток текущая ветка, у коммитов число выбранных, у файлов их число, у описания число коммитов.
- Развёрнутые секции делят высоту колонки, границы между ними перетаскиваются. Свёрнутость и размеры запоминаются.
- Пользователь планирует позже развивать дерево веток, поэтому секция веток есть всегда, даже если обычно свёрнута.
- Строка коммита — две строки (сообщение; автор и время), если колонка уже 520 px; при ширине от 540 px — одна строка с колонками Subject | Author | Date, как в WebStorm.
- Тулбар: ↻ «обновить», ⇣ «fetch».

### Вкладка «Diff»

- Клик по файлу в секции «Файлы» открывает вкладку «Diff» с диффом этого файла. Вкладка одна на репозиторий: следующий клик заменяет её содержимое.
- ← → (и Alt+↑/↓) листают файлы того выделения, из которого файл открыли; счётчик «i/N files». Смена выделения в сайдбаре вкладку не трогает до следующего клика по файлу.
- Внутри — всё, что было в диффе: шапка с путём и хешами «до..после», split/unified, «весь файл», F7/Shift+F7 по изменениям, подсветка синтаксиса, только чтение.
- Технически — custom editor Орки для файла-якоря `.orca-git-log.gitdiff` в корне рабочего пространства, которое держит репозиторий (скрыт через `.git/info/exclude`), тот же обход API, что был у вкладки «Git» (см. «Ограничение Орки»). Вкладка привязана к репозиторию, из которого открыта.

## Что умеет первая версия

### Ветки

- Дерево: HEAD сверху, затем Local и Remote, ветки группируются в папки по префиксу до `/` (`bug/`, `feature/`), как в WebStorm. Теги — как в движке.
- Поиск по имени ветки или тега.
- *Решение дизайна:* клик по ветке задаёт фильтр лога этой веткой (как Branch-фильтр в WebStorm; пользователь «выбирает HEAD» именно так). В движке клик прыгает к коммиту ветки, а фильтр — по двойному клику.
- Меню по правому клику: действия, которые уже есть в движке (checkout, новая ветка от неё, checkout удалённой как локальной), плюс новые — **переименовать**, **удалить**, **merge в текущую**, **rebase текущей на неё** (решение пользователя).
- Удалять можно только локальные ветки. Неслитую ветку (`git branch -D`) — только после подтверждения с предупреждением. Удаление удалённой ветки в первую версию не входит: оно затрагивает других и не отменяется.

### Коммиты

- Граф веток, ref-метки, автор, дата; коммиты вне HEAD приглушены — как в движке.
- Поиск по тексту или хешу, фильтры Branch, User, Date, Paths — из движка.
- Выбор нескольких коммитов: Ctrl/Shift-клик, клавиатура — из движка.
- Меню по правому клику: reset, cherry-pick, revert, drop, reword, squash, fixup, interactive rebase, new branch, new tag, copy hash, create patch — из движка, с его предупреждениями и Undo.

### Файлы

- Изменённые файлы **всего выделения**, а не одного коммита (сейчас движок показывает файлы одного коммита — это главная доработка).
- Правило объединения как в WebStorm: для каждого файла берётся состояние до самого раннего выбранного коммита, который его менял, и после самого позднего такого коммита. Для непрерывного диапазона это обычный `git diff <старший>^ <младший>`. Для разрывного выделения в дифф файла попадут и изменения невыбранных коммитов между ними — так же делает WebStorm. «Ранний» и «поздний» — по топологии графа, а не по дате.
- Merge-коммит сравнивается с первым родителем, как в движке.
- Дерево по папкам; кнопки «развернуть всё» и «свернуть всё»; статус файла (добавлен, изменён, удалён, переименован).
- Один клик по файлу открывает его дифф во вкладке «Diff» (в движке — двойной клик и дифф поверх лога).

### Дифф

- Во вкладке «Diff» (см. «Раскладка»), не поверх лога.
- Side-by-side и unified, подсветка изменённых слов, режим «весь файл», переход по изменениям F7 / Shift+F7 — из движка.
- Переход к предыдущему и следующему файлу выделения: стрелки ← → и счётчик «1/6 files», как в WebStorm.
- Над диффом — хеши «до» и «после» и путь файла.
- **Подсветка синтаксиса** по языку файла (решение пользователя: в первой версии). Подсветчик и грамматики встроены в плагин: сети у плагина нет, лимиты Орки — 50 MiB на плагин и 1 MiB на файл. Цвета подсветки — своя палитра в стиле WebStorm, отдельно для тёмной и светлой темы Орки (решение пользователя): у тем Орки цвета токенов есть, но фреймам плагинов Орка их не отдаёт, а читать её внутренние файлы — костыль. В Орку — issue с просьбой отдавать эти цвета плагинам; когда появится, перейти на них. Выбор подсветчика — за исполнителем.
- Только чтение.

### Описание коммита

- Четвёртая секция панели в сайдбаре (см. «Раскладка»).
- Макет — `sidebar-details-mockup.html`, вариант «Б. Список с раскрытием» (выбор пользователя).
- По строке на каждый выбранный коммит: короткий хеш, заголовок, автор; сверху новый. Клик по строке раскрывает полное описание: всё сообщение, автор и email, коммитер, дата, ветки, в которых есть коммит (данные `commit.details` движка).
- *Решение дизайна:* при одном выбранном коммите его строка раскрыта сразу; при нескольких все свёрнуты. Раскрытые строки остаются раскрытыми, пока выделение не меняется.

### Общее

- Кнопка ↻ **перечитать** лог и ветки (решение пользователя). Автообновление при изменениях репозитория — из движка.
- Кнопка **fetch** (решение пользователя): забирает изменения со всех remote, рабочее дерево не трогает. Пароль не спрашивает (`GIT_TERMINAL_PROMPT=0`, как в движке), работает через SSH-агент и хранилище учётных данных git. Ошибку и таймаут показывает сообщением. *Решение дизайна:* `git fetch --all` без `--prune`, чтобы fetch ничего не удалял.
- Update Project (fetch плюс merge/rebase) — потом.
- Работа с несколькими рабочими пространствами и выбор репозитория — как в движке.

## Внешний вид

- Раскладка, плотность строк, иконки-кнопки в тулбарах, деревья с шевронами — как в WebStorm (см. скриншот).
- Язык интерфейса — язык Орки (решение пользователя): в плагине английский и русский каталоги, все строки и сообщения переводятся; ошибки самого git остаются на английском.
- *Решение дизайна:* цвета и шрифты берутся из текущей темы Орки через её CSS-переменные `--orca-*`. Движок так уже делает, и это сохраняем, чтобы плагин не выбивался из Орки при смене темы.
- Интерфейс остаётся HTML-страницей в изолированном фрейме (`ui: "html"`), а не панелью из компонентов Орки (согласовано с пользователем). Причины: custom editor (вкладка) бывает только HTML; у компонентов нет своей отрисовки (граф), меню по правому клику, мультивыбора в `Tree`, растягиваемых секций, а рендер ограничен 5000 узлами. Сайдбар на компонентах стал бы вторым, непохожим интерфейсом.

## Бэкап перед опасными операциями

Решение пользователя 2026-11-10. Макет — `backup-mockup.html` (вариант «А» и блок «После операции»).

Зачем: плагин запускает git на репозиториях своих пользователей, и операция, переписывающая историю или удаляющая ветку, не должна оставлять человека без пути назад.

- **Когда предлагается.** squash, fixup, drop, reword, interactive rebase, «rebase текущей на эту», reset любого режима, удаление неслитой ветки (`-D`). Не предлагается для merge, cherry-pick, revert, undo commit, checkout, новой ветки или тега, fetch: они только добавляют коммиты или ничего не трогают, и у них есть Undo.
- **Как спрашивается (вариант «А»).** В уже существующем подтверждении операции — галочка «Back up <ветка> first» (включена по умолчанию), выбор «ветка / тег» и поле с готовым именем, которое можно исправить. Одно окно на одну операцию: удаление, squash или fixup нескольких коммитов — одна операция и один бэкап (он указывает на старую вершину ветки и сохраняет все затронутые коммиты).
- **reset `--hard`** при незакоммиченных изменениях — вторая галочка «Also save uncommitted changes to the stash» (включена): снимок через `git stash create` + `git stash store -m "<сообщение>"`, рабочая копия при этом не меняется.
- **Удаление неслитой ветки** — бэкапом сохраняется сама удаляемая ветка.
- **Вид по умолчанию** — ветка (у пользователя уже есть привычка держать бэкап-ветки в папке `backup/`). Последний выбор «ветка / тег» запоминается.
- **Имя.** `backup/<ветка>-<ГГГГММДД-ЧЧММ>`; для отделённой HEAD — `backup/detached-<короткий хеш>-<ГГГГММДД-ЧЧММ>`; при совпадении — суффикс `-2`, `-3`… Проверка `git check-ref-format`; занятое имя — ошибка прямо в поле.
- **Надёжность.** Бэкап создаётся в том же запросе к воркеру до операции; если он не удался, операция не начинается. Существующие ссылки не перезаписываются: `git branch --no-track <имя> <хеш>` и `git tag <имя> <хеш>` без `-f`.
- **После операции.** В баннере — имя бэкапа, Undo и «Show backup» (выделяет бэкап в дереве веток).
- **Восстановление.** В меню бэкап-ветки или бэкап-тега (имя начинается с `backup/`): «Restore <текущая ветка> to This Backup…» — `reset --keep` с подтверждением (и снова с предложением бэкапа); git сам отказывается, если затёр бы локальные изменения. «Delete Backup» — с подтверждением.
- **Настройка плагина** «Offer a backup before risky operations» (по умолчанию включена).

- PR в апстрим.
- Кнопки настроек, консоль git, прочие панели WebStorm — потом.
- Коммит, stage, незакоммиченные изменения — это делает source control Орки.

## Анти-цели

- Вид, похожий на нынешний вид апстрима, — его пользователь как раз не хочет.
- Плагин, который выбивается из темы Орки.
- Потеря защит движка: предупреждений о переписывании запушенных коммитов и Undo после переписывания.
- Изменения в рабочем дереве пользователя, кроме файла-якоря и записи в `.git/info/exclude`.

## Репозиторий и установка

- *Решение дизайна:* форк на GitHub `predmaxim/orca-git` (публичный, как любой форк; до 2026-11-10 назывался `orca-git-log-panel` — переименован, чтобы Орка показывала свой аватар, а не аватар оригинала: она берёт аватар родителя у форков с тем же именем), клон в `~/Projects/orca-git-log`, remote `upstream` на оригинал.
- *Решение дизайна:* форк делается от свежего `main` апстрима (он уже ушёл дальше установленной 0.1.5).
- Плагин, установленный из git URL форка, получит id `predmaxim.git-log`; при установке из папки (разработка) — `local.git-log`. Оригинальный `emamalet.git-log` выключить.
- *Решение дизайна:* ошибки, найденные при проверке движка, исправляются отдельными коммитами, чтобы их можно было отдать апстриму. На каждую предлагаем пользователю issue в апстрим; публикуем только с его согласия.
- *Решение дизайна:* если `localStorage` фрейма не переживает перезапуск Орки, свёрнутость и размеры секций хранятся через `storage:own` (это новое разрешение — показать пользователю при установке).
- *Решение дизайна:* при конфликте в merge, rebase или cherry-pick следуем правилу движка — прервать операцию и сообщить.
- Установка: `orca plugin install <папка или git URL>`; доступ, который просит плагин, показать пользователю до `--approve`.
- Этот документ и макеты лежат в `docs/superpowers/specs/` форка. Данные рабочих репозиториев пользователя (скриншоты, коммиты, имена коллег, пути) в публичный репозиторий не попадают: в макетах вымышленные данные, остальное — в `.local/`.
- README форка описывает, чем форк отличается от оригинала и как подтягивать апстрим. По правилам пользователя документация обновляется вместе с кодом.
- В коммитах — без ИИ-соавторов.

## Отклонения от дизайна и итоги реализации

- **Подсветка синтаксиса.** Палитры не из темы Орки: у тем есть `tokenColors`, но фреймам плагинов Орка отдаёт только переменные `--orca-*` и класс `light`/`dark`. Читать файл темы с диска самим нельзя (внутреннее состояние Орки, обход платформы), поэтому в плагине свои палитры в стиле WebStorm, светлая и тёмная. Issue в Орку с просьбой отдавать цвета токенов — черновик в `docs/orca-issues.md`.
- **Язык интерфейса** следует Орке (`orca.locale`): каталоги `en` и `ru`, все строки интерфейса и сообщения воркера идут через `t()`. Вывод самого `git` не переводится.
- **Две линии в строке коммита.** В колонке уже 520 px строка коммита занимает две линии (сообщение, под ним автор и время), от 540 px строка снова одна. Высота строки не прыгает при переключении.
- **«Описание» в левой колонке** (решение пользователя 2026-11-09, секция под диффом не делалась): уже записано в разделе «Раскладка».
- **Граф в сайдбаре.** Строка коммита в сайдбаре показывает полный граф веток, а не точку цвета ветки, как задумано в разделе «Панель в правом сайдбаре»: колонка секций писалась общей для сайдбара и прежней вкладки «Git», и граф в ней остался.
- **Сохранность раскладки** проверена только перезагрузкой фрейма плагина (`orca plugin dev reload`): свёрнутость секций и размеры пережили её, `localStorage` хватает, `storage:own` не понадобился. Проверка с полным перезапуском Орки оставлена пользователю.
- **Живая проверка** сделана на демо-репозитории (вымышленные авторы и коммиты, выделение из шести коммитов через два merge, дерево файлов, дифф split и unified, список описания, ветки с папками). На рабочем репозитории пользователя проверку делает он сам: открытие вкладки там создаёт файл-якорь.
- **Вкладка «Diff» (задача 14c).** Что показывает вкладка, воркер хранит в памяти по корню репозитория: сайдбар отдаёт выделение и номер файла (`diff.open`), вкладка читает их при старте и по событию `diff.show` (`diff.state`). Поэтому вкладка, восстановленная после перезапуска Орки, показывает заглушку до следующего клика по файлу. Листание ← → во вкладке сообщается воркеру (`diff.index`): он запоминает номер файла (пересозданный фрейм вкладки откроется на нём) и шлёт `diff.current`, по которому сайдбар подсвечивает тот же файл, раскрывает его папку и прокручивает к нему, если файл ещё есть в его выделении. Новый `diff.open` при этом не отправляется. Якорь пишется только в рабочее пространство, чей top level равен корню репозитория сайдбара; если такого нет, сайдбар показывает ошибку и ничего не пишется. Якорь создаётся один раз (`wx`: не идёт по ссылкам и не заменяет файлы) и потом не переписывается; если под его именем уже лежит что-то другое (файл пользователя, ссылка, папка, якорь другого репозитория), вкладка не открывается, а `info/exclude` не трогается. Существующий файл проверяется без перехода по ссылкам и без ожидания на FIFO (`O_NOFOLLOW | O_NONBLOCK`, `fstat`, чтение не больше 4 KiB). Ошибка файловой системы при создании якоря показывается переведённым сообщением с её кодом; якорь, который не удалось дописать, удаляется, чтобы следующие клики не считали его чужим.
- **Не больше 2000 файлов во вкладке.** Воркер принимает до 2000 файлов (проверка на границе вместе с путями, буквами статуса и хешами). Если выделение меняет больше файлов, сайдбар отправляет 2000 вокруг выбранного, и счётчик «i/N files» считает только их.
- **Alt+↑/↓ в списке коммитов** больше не пропускаются мимо списка (раньше их забирал дифф в том же фрейме) и двигают выделение, как обычные стрелки.
- **Скриншоты README.** Снимок сайдбара в запущенной Орке показывает активное рабочее пространство пользователя, поэтому колонка секций вырезана из прежних снимков демо-репозитория (тот же код и тот же тулбар ↻ ⇣) и поставлена справа от нового снимка вкладки «Diff» с тем же выделением: так Орка их и располагает, а каталогу нужны снимки не меньше 1280×800. Отдельный снимок вкладки «Diff» (`diff-dark.png`) — целиком новый.
- **Бэкап (задача 15).** Галочка «Also save uncommitted changes to the stash» показывается при выборе Hard всегда, а не только при незакоммиченных изменениях: сайдбар не знает состояние рабочего дерева, а отдельный запрос ради этого не заводили; при чистом дереве `git stash create` ничего не создаёт. С этой галочкой вопрос «Незакоммиченные изменения будут потеряны» не задаётся; неотслеживаемые файлы в stash не попадают. Сообщение stash английское (`Git plugin backup before reset --hard (<ветка>)`, как в плане): это запись в репозитории, а не строка интерфейса.
- **Где спрашивается бэкап.** Fixup, drop и «rebase текущей на эту» раньше без запушенных коммитов шли без окна; теперь, пока предложение бэкапа включено, они показывают подтверждение с ним (с выключенной настройкой — как раньше). У удаления неслитой ветки предложение стоит во втором окне («слита не полностью, всё равно удалить?»), то есть именно перед `-D`. Выбор «ветка / тег» запоминается в `backupKind` сразу при переключении, даже если окно потом отменили.
- **Проверка имени бэкапа.** В окне — только пустое и занятое имя (среди веток и тегов). Имя, которое отвергает `git check-ref-format`, отклоняет воркер: окно уже закрыто, баннер говорит почему, ничего не сделано.
- **HEAD проверяет и воркер.** `action.run` и `branch.run` принимают `expectHead` — HEAD, который показало подтверждение; если HEAD другой, воркер ничего не делает (ни бэкапа, ни git). Бэкап обязан указывать на этот HEAD, а при удалении ветки — на её текущую вершину. Undo из баннера передаёт HEAD, который оставила операция.
- **Удаление бэкапа** — отдельный запрос `backup.delete` (`src/worker/backup.ts`): только имена `backup/…` и только пока ссылка указывает на коммит, показанный в дереве. «Restore…» выключен для бэкап-ветки, которая сама сейчас текущая.

## Проверка

- Тесты движка и новые тесты на объединение файлов выделения: `orca plugin test`.
- `orca plugin check` и снимки `orca plugin shot` сайдбара и вкладки «Diff».
- Живая проверка в запущенной Орке на реальных репозиториях пользователя.
