# Плагин «Git» — что войдёт в следующую версию

Дата: 2026-11-10. Статус: список согласован с пользователем; перед реализацией каждого пункта — короткий дизайн (brainstorming) и план.

Пункты выбраны пользователем из предложенного списка удобств. Нумерация — как в предложении.

## Берём

2. **Отметки «просмотрено» у файлов**, как Viewed на GitHub: отметка у файла в секции «Файлы», счётчик «просмотрено N из M» в заголовке секции; отметки хранятся для выделения коммитов (и сбрасываются, если файл изменился в новых коммитах — уточнить в дизайне).
3. **Клавиатура.** Навигация по дереву файлов (стрелки, Enter — открыть дифф, отметка «просмотрено» одной клавишей) и переходы по диффу. Требование пользователя: сначала проверить пересечения с сочетаниями Орки и ОС (Omarchy/Hyprland: `hyprctl binds`; сочетания Орки и её плагинов), и по возможности обойтись одной-двумя клавишами без модификаторов там, где фокус в плагине.
4. **В диффе:**
   - сворачивать неизменённые куски с кнопкой «развернуть» (как в WebStorm);
   - переход из строки диффа к той же строке файла в редакторе Орки (`editor.open`; нужен ли переход к строке в API — проверить, сейчас `editor.open` принимает только путь).
5. **«Сравнить с…»**: файлы и дифф между текущей веткой и выбранной (например `main`) без выделения коммитов.
6. **«История файла»** из меню файла: лог по одному пути (в движке есть фильтр Paths).
7. **Меню файла**: открыть файл, скопировать путь, скопировать хеш.
9. **Запоминать** последнее выделение и открытый файл для каждого воркспейса между перезапусками Орки.
10. **Пункт в статус-баре Орки** (пользователь: «очень нужно»): текущая ветка, ahead/behind относительно upstream, кнопка fetch; обновляется по событиям (смена воркспейса, изменения в `.git`), без опроса по таймеру.

## Не берём сейчас

1. «Выбрать мои коммиты» одним действием.
4 (частично). «Игнорировать пробелы», перенос строк, счётчик «N differences».
8. Быстрые фильтры лога («мои», «не запушенные», «с последнего fetch»).
