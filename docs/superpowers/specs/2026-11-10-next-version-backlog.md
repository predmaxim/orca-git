## Берём

2. **Отметки «просмотрено» у файлов**, как Viewed на GitHub: отметка у файла в секции «Файлы», счётчик «просмотрено N из M» в заголовке секции; отметки хранятся для выделения коммитов (и сбрасываются, если файл изменился в новых коммитах — уточнить в дизайне).
3. **Клавиатура.** Навигация по дереву файлов (стрелки и Enter — сделано 2026-11-10 вместе с деревом веток, см. дизайн, «Клавиатура в деревьях»; Enter — открыть дифф, отметка «просмотрено» одной клавишей) и переходы по диффу. Требование пользователя: сначала проверить пересечения с сочетаниями Орки и ОС (Omarchy/Hyprland: `hyprctl binds`; сочетания Орки и её плагинов), и по возможности обойтись одной-двумя клавишами без модификаторов там, где фокус в плагине.
4. **В диффе:**
   - ~~сворачивать неизменённые куски с кнопкой «развернуть» (как в WebStorm)~~ — не делаем (2026-11-10): Whole file переключает «3 строки контекста / весь файл» (`-U3` / `-U1000000`, `src/worker/selection.ts:92`), а с `F7` и полосой изменений (п. 14) этого хватает;
   - переход из диффа к файлу в редакторе Орки — пока к файлу, не к строке: `editor.open` принимает только путь (проверено: host API Орки 1.4.253, 2026-11-10). Клавиша `o` (дизайн системы клавиш).
5. **«Сравнить с…»**: файлы и дифф между текущей веткой и выбранной (например `main`) без выделения коммитов.
6. **«История файла»** из меню файла: лог по одному пути (в движке есть фильтр Paths).
7. **Меню файла**: открыть файл, скопировать путь, скопировать хеш.
9. **Запоминать** последнее выделение и открытый файл для каждого воркспейса между перезапусками Орки.
10. **Пункт в статус-баре Орки** (пользователь: «очень нужно»): текущая ветка, ahead/behind относительно upstream, кнопка fetch; обновляется по событиям (смена воркспейса, изменения в `.git`), без опроса по таймеру.
    - Добавлено 2026-11-10: из статус-бара **выбрать ветку и переключить** на неё воркспейс. Ограничение: нажатие на пункт только запускает команду воркера (`statusBarItems[].command`), а показать список выбора воркеру нечем — такого метода в API нет (проверено: host API 1.4.253). Как показать выбор — решить в дизайне п. 10. Переход — через проверку Checkout из дизайна системы клавиш.

## Добавлено позже

11. **Все файлы выделения подряд во вкладке «Diff»** (предложение пользователя 2026-11-10, в будущую версию). Если файл не выбран, или по Esc (или другому сочетанию — проверить пересечения, см. п. 3) — вкладка показывает дифф всех файлов выделения стопкой, как «Files changed» на GitHub. У каждого блока липкий заголовок: свернуть/развернуть, статус, путь, +/−, «открыть файл»; клик по заголовку или по файлу в сайдбаре — режим одного файла. Блоки подгружаются по мере прокрутки (`IntersectionObserver`, без таймеров), большие и бинарные — свёрнуты с кнопкой «показать». Хорошо сочетается с п. 2 (отметка «просмотрено» сворачивает блок). Макет — `diff-stack-mockup.html`.

12. **Полное управление с клавиатуры, как в Omarchy и lazygit** (пользователь 2026-11-10; расширяет п. 3). Однобуквенные сочетания, когда фокус в плагине и не в поле ввода: переход между секциями и вкладкой «Diff», движение по спискам, выбор, открыть, свернуть, действия с коммитами и ветками; `?` — подсказка со всеми сочетаниями. Каждую клавишу проверить на пересечения с Оркой и Hyprland (`hyprctl binds`); опасные действия по одной клавише только через подтверждение (и с бэкапом из Task 15).
    - Сделано 2026-11-10 — вариант «А» (`2026-11-10-keyboard-design.md`): цифры между областями и вкладкой «Diff», `f` — свернуть, `/` — поиск, буквы — видимые кнопки областей, `?` — подсказка, `r` / `Shift+F` — Refresh / Fetch.
    - Вариант «Б» заменён системой клавиш (2026-11-10, `2026-11-10-key-system-design.md`): буква — действие с объектом, Shift+буква — с панелью (повторно — назад), `Space` — меню с теми же буквами; буква, меняющая репозиторий, — всегда через диалог; Checkout с изменениями предлагает стэш.
13. **Ревью с комментариями к строкам и отправкой агенту** (пользователь 2026-11-10). В диффе — комментарий к строке или диапазону (как на GitHub); комментарии копятся в «ревью» выделения; в конце — «Отправить агенту»: плагин собирает текст (файл:строка, кусок кода, комментарий) и передаёт агенту на доработку или ответы.
    - Что есть в API Орки (проверено: `orca skills get orca-plugin-authoring --reference references/host-api.md`): `agent.launch` (запустить агента в воркспейсе с промптом, право `agent:launch`), `agents.list` (агенты воркспейса, `agent:read`), `terminal.sendText` (в терминал агента, `terminal:send`). Новые права — новое одобрение при установке.
    - Встроенных комментариев к строкам в Орке нет: `orca worktree set --comment` — это строка статуса на карточке воркспейса (проверено: `orca worktree set --help`, раздел «Worktree Comments» в `orca skills get orca-cli`).
    - Решить в дизайне: где хранить комментарии (`storage:own`, привязка к файлу, стороне диффа, строке и коммиту; что делать при сдвиге строк), кому отправлять (выбрать агента из `agents.list` или запустить нового), как показывать ответы (агент отвечает в своём терминале; чтение ответа через `terminal.read` — отдельное право).

14. **Полоса изменений у правого края диффа** (пользователь 2026-11-10). В режиме Whole file — карта всего файла у правого края, рядом с полосой прокрутки: метки цветом изменений (добавлено / изменено / удалено), шириной несколько пикселей и высотой с изменённый участок в масштабе файла; клик по метке — переход к участку.

15. **Checkout: «в воркспейсе идёт работа»** (пользователь 2026-11-10; отложено, сначала — простой вариант из дизайна системы клавиш). Показывать диалог перед переходом и без изменений в файлах, если:
    - агент этого воркспейса не закончил (`agents.list`: `working`, `blocked`, `waiting`; нужно право `agent:read` — новое одобрение при обновлении);
    - в терминале воркспейса запущен процесс, кроме самой оболочки (dev-сервер, тесты, vim, агент). API Орки этого не даёт: `workspace.readContext` отдаёт только id и заголовок терминала (проверено: host API 1.4.253). Способ — `/proc` (Linux): процесс с управляющим терминалом, рабочей папкой внутри воркспейса и не лидер сессии. Проверено 2026-11-10 на этом воркспейсе: так находится `claude` (tty 34821), его `bash` (лидер сессии) отсеивается, процессы без терминала (языковые серверы редактора) не попадают. На macOS и Windows — пропускать и написать об этом в README;
    - в редакторе Орки есть несохранённые вкладки с файлами воркспейса: после перехода их сохранение перепишет файлы новой ветки старым текстом. Узнать нечем: в API только хук `editor.save.before` (проверено: host API 1.4.253).
    - Для второго и третьего — черновик issue в Орку (состояние терминала «занят», несохранённые вкладки) в `docs/orca-issues.md`.
    - Другие воркспейсы не мешают: у каждого worktree своя папка. Ветку, занятую другим worktree, и `index.lock` git отклоняет сам (по документации git; на стенде не проверено).
