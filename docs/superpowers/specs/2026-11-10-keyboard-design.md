# Управление с клавиатуры, как в lazygit — дизайн

Дата: 2026-11-10. Статус: одобрен пользователем 2026-11-10. Это часть пункта 12 бэклога (`2026-11-10-next-version-backlog.md`): вариант «А» — буквы получают только видимые элементы областей; действия из меню коммита и ветки по буквам — следующим шагом.

## Зачем

Пользователь хочет работать с панелью «Git» без мыши, как в lazygit: цифрой перейти в нужную область, буквой нажать то, что в ней видно, `/` — искать. Сейчас стрелки ходят по спискам и деревьям (версия 0.2.1), но между областями — только Tab и мышь, а фильтры и кнопки — только Tab или мышь.

## Цели

- Цифры `1`–`4` переводят фокус в «Ветки», «Коммиты», «Файлы», «Описание»; `0` — во вкладку «Diff».
- `f` сворачивает и разворачивает текущую область целиком.
- `/` — поиск в текущей области.
- Видимые элементы области — по первой букве своей надписи (`u` — User в «Коммитах»).
- `?` — подсказка со всеми клавишами.
- Тонкая линия слева вдоль выбранной области.

## Не цели

- Буквы для действий из контекстного меню (Cherry-Pick, Reset, Rebase и т. д.) — следующий шаг (вариант «Б»): там совпадают первые буквы (C ×4, R ×2, N ×2) и нужны свои буквы, как в lazygit.
- `j`/`k` и другие клавиши lazygit, которых пользователь не просил.
- Переназначение клавиш в настройках.
- Глобальные сочетания Орки (`contributes.keybindings`): клавиши работают, только когда фокус в плагине.

## Анти-цели

- Буква не должна срабатывать, пока человек печатает: в поле ввода, в меню, в диалоге.
- Ни одна клавиша не меняет репозиторий: в этом шаге только переходы, фильтры, свёртка, поиск, Refresh и Fetch (Fetch только читает с удалённого).
- Не ломать уже работающие сочетания: стрелки, Page Up/Down, Home/End, Ctrl+A, Ctrl+C, Shift+F10, Enter, Space, Esc в поиске, F7, ← → и Alt+↑/↓ во вкладке «Diff».

## Ограничения

- **Фреймы.** Панель и вкладка «Diff» — разные фреймы. Клавиша доходит только до фрейма с фокусом; общий обработчик на оба невозможен.
- **API Орки** (проверено: `orca skills get orca-plugin-authoring --reference references/host-api.md`, 2026-11-10). Открыть вкладку может воркер (`editor.open`, уже так делает `openDiff`, `src/worker/main.ts:155`). Сфокусировать панель из вкладки или из воркера нечем: у `commands.run` только `sidebar.right.toggle` и подобные переключатели.
- **Пересечения.** Hyprland: глобальных биндов без модификаторов на буквы, цифры, `/`, `.`, `?` нет; буквы заняты только внутри сабмапов вроде vimarchy (проверено: `hyprctl binds -j`, 2026-11-10). Орка отдаёт плагину только аккорды из `contributes.keybindings`; голые клавиши в своём фрейме — наши.
- **Раскладка.** Пользователь пишет по-русски: клавиши сравниваются по физической кнопке (`event.code`: `KeyU`, `Digit1`, `Slash`, `Period`), а не по символу, чтобы `u` работала и в русской раскладке.
- **Последняя открытая область не сворачивается** — так уже работает клик по заголовку (`src/ui/sections.ts:97-98`).

## Подходы

1. **Одна таблица клавиш** — выбран (решение пользователя 2026-11-10). Модуль `src/ui/keys.ts`: список записей «физическая клавиша (+Shift) → область или везде → подпись для подсказки → действие». Один обработчик `keydown` на документе панели находит текущую область и запускает действие. Подсказка `?` строится из той же таблицы и не может разойтись с работой клавиш; чистая функция поиска записи проверяется тестом, и тот же тест ловит две одинаковые клавиши в одной области. Минус: новый модуль и ссылки на кнопки из `app.ts`.
2. **Обработчик в каждой области**, как сейчас у списка коммитов (`src/ui/app.ts:766`), плюс общий для цифр. Отвергнут: подсказку пришлось бы вести отдельно, совпадения клавиш никто не проверяет.
3. **Атрибут на кнопке** (`data-key="u"`), общий обработчик кликает кнопку в текущей области, подсказка собирается из DOM. Отвергнут: фокус областей, свёртка и поиск всё равно пишутся отдельно, а связь клавиша ↔ кнопка спрятана в разметке и не тестируется без DOM (тесты плагина идут в Node без DOM).

## Клавиши

Решения пользователя — без пометки; решения, принятые в разговоре как предложение и одобренные пользователем («всё ок», 2026-11-10), помечены «(предложено)».

**Везде в панели** (фокус в панели, не в поле ввода, меню или диалоге; без Ctrl, Alt, Meta):

| Клавиша | Действие |
|---|---|
| `1` `2` `3` `4` | фокус в «Ветки» / «Коммиты» / «Файлы» / «Описание»; свёрнутую область сначала развернуть (предложено) |
| `0` | вкладка «Diff» этого репозитория (см. «Вкладка Diff по `0`») |
| `f` | свернуть или развернуть текущую область |
| `/` | поиск в текущей области: «Ветки» — поле поиска веток, «Коммиты» — текст или хеш; в «Файлах» и «Описании» поля нет, клавиша ничего не делает (предложено) |
| `r` | Refresh (предложено) |
| `Shift+F` | Fetch (предложено: `f` занята свёрткой) |
| `?` (`Shift+/`) | подсказка (из бэклога) |

**В области:**

- «Коммиты»: `b` Branch, `u` User, `d` Date, `p` Paths (открыть фильтр, как кликом), `.` — переключатель `.*`, `c` — переключатель `Cc` (предложено: по надписи на кнопке); `Shift+B` / `Shift+U` / `Shift+D` / `Shift+P` — сбросить свой фильтр, как крестик на кнопке (решение пользователя после живой проверки 2026-11-10, вариант «Б»).
- «Файлы»: `e` — развернуть всё, `c` — свернуть всё (по подсказкам кнопок Expand all / Collapse all).
- «Ветки», «Описание»: своих букв нет.

**Во вкладке «Diff»** (свой фрейм, тот же модуль `keys.ts` с таблицей вкладки): `s` Split, `u` Unified, `w` Whole file. ← →, Alt+↑/↓ и F7 / Shift+F7 остаются как есть (`src/ui/diff.ts:243-253`).

**Esc** в поле поиска: если в поле есть текст — очищает его, как сейчас у поиска коммитов (`src/ui/app.ts:568`); если поле пустое — возвращает фокус в список своей области (предложено). У поиска веток Esc сейчас не обработан (только `input`, `src/ui/app.ts:615`) — он получает то же поведение.

## Поведение

- **Текущая область** — секция, внутри которой фокус. Если фокус нигде (кликнули по пустому месту) — последняя область, где он был. До первого фокуса области нет: работают цифры, `0`, `r`, `Shift+F`, `?`; `f`, `/` и буквы областей ничего не делают.
- **Куда ставится фокус по цифре:** «Ветки» — строка-остановка Tab дерева веток; «Коммиты» — список (`viewport`), курсор и выделение не меняются; «Файлы» — строка-остановка дерева файлов, а если файлов нет — тело секции; «Описание» — первая строка списка или тело секции. Тело секции для этого получает `tabindex="-1"`.
- **Линия области** (решение пользователя: «слева вдоль области», цвет — кольцо фокуса Орки `--orca-ring`): вертикальная линия 2 px по левому краю секции текущей области, от заголовка до низа, без сдвига содержимого (`box-shadow: inset` или псевдоэлемент). Остаётся на последней области, когда фокус уходит из панели (во вкладку, в терминал): видно, куда вернёшься. Фокус по-прежнему показывается и на строке (решение 2026-11-10 в основном дизайне не меняется: линия — метка области, а не рамка фокуса).
- **`f`** сворачивает текущую область, как клик по её заголовку (тот же код в `sections.ts`, без копии), и фокус встаёт на кнопку-переключатель в заголовке (`sec-toggle`), чтобы `f` или Enter развернули обратно. Свернуть последнюю открытую область нельзя — ничего не происходит. До этой работы свернуть область с клавиатуры тоже можно (Tab до `sec-toggle` и Enter); `f` делает это одной клавишей.
- **`/`** фокусирует поле поиска и выделяет его текст.
- **Свёрнутая текущая область** (после `f` фокус на её `sec-toggle`, и она остаётся текущей): `/` и буквы области сначала разворачивают её, как цифры, затем делают своё (решение автора дизайна после проверки: тело свёрнутой секции — `display: none`, `src/ui/styles.css:450`, и иначе `/` ушёл бы в скрытое поле, а `e`/`c` в «Файлах» — кнопки заголовка — меняли бы невидимое дерево).
- **Буквы фильтров** делают то же, что клик по кнопке: открывают её всплывающее окно. Окно закрывается по Esc, но фокус сейчас не возвращается: `filters.ts` не передаёт `onClose` в `showPopover` (`src/ui/menu.ts:123`), и фокус падает на `body`. В этой работе закрытие окна фильтра возвращает фокус в список коммитов (сначала — на кнопку фильтра; после живой проверки пользователь попросил список, 2026-11-10). В открытом окне ↑/↓ ходят по полю поиска и пунктам (у Date — по пресетам, окно открывается на первом), пробел или Enter выбирают пункт, фокус остаётся на нём после перерисовки.
- **`?`** открывает окно (существующий `dialog`, `src/ui/dialogs.ts:25`) со списком из таблицы: сначала «везде», затем по областям, затем вкладка «Diff»; подписи через `t()` на английском и русском. Клавиша показывается латиницей.
- **Подсказки кнопок** (`title`) получают клавишу: «User (u)».
- Обработчик не трогает событие, если оно уже обработано (`defaultPrevented`), если цель в поле ввода, `select`, `textarea`, `[contenteditable]`, в меню или диалоге, и если нажаты Ctrl, Alt или Meta. Обработанное событие получает `preventDefault()`.
- Пока стоит «занятый» оверлей (`busy`, `src/ui/dialogs.ts:365`), клавиши не работают — как и мышь.

## Вкладка «Diff» по `0`

- `0` — переход во вкладку, как `0` в lazygit, а не перезагрузка (решение автора дизайна после проверки: обычный `openDiff` всегда шлёт `diff.show`, `src/worker/main.ts:163`, и вкладка строит вид заново, `src/ui/diff-app.ts:42,74`, теряя прокрутку, `src/ui/diff.ts:205`). Если у воркера уже есть состояние вкладки этого репозитория (`diffStates`), новый запрос воркера `diff.focus` только вызывает `editor.open`, без нового состояния и без `diff.show`. Если состояния нет — обычный `openDiff` с файлом, текущим в «Файлах» (`currentFile`), иначе с первым файлом выделения; если выделения нет — баннер `filesPlaceholder` («Выберите коммиты, чтобы увидеть их файлы») (предложено). Новый запрос — в `src/shared/protocol.ts` и в тестах воркера.
- Переходит ли при этом фокус клавиатуры во фрейм вкладки — **не проверено**. Проба в начале работы (см. ниже). Если не переходит, `0` всё равно выводит вкладку вперёд, а фокус в неё ставит клик.
- Вернуться из вкладки в панель по `1`–`4` — **скорее всего, нельзя** (нет API фокуса панели). Проба проверит, может ли панель взять фокус сама по событию от вкладки (`plugin.request` → воркер → `panels.post` → `element.focus()` в панели). Если Chromium не даёт фрейму без жеста пользователя забрать фокус, `1`–`4` во вкладке не назначаются, а в подсказке вкладки написано, что в панель возвращаются кликом.

## Пробы в начале работы

Одна одноразовая проба в dev-копии (`orca plugin dev load .`), до основной работы, результат записывается сюда:

1. Доходят ли голые буквы, цифры, `/` и `.` до фрейма панели, или Орка забирает какие-то раньше (стрелки и Enter доходят — проверено в 0.2.1; буквы не проверены).
2. После `0` (`editor.open`) — получает ли фрейм вкладки нажатия клавиш без клика.
3. Может ли панель забрать фокус по событию от вкладки.
4. Видна ли линия области, когда фокус ушёл из панели (если `:focus-within` гаснет — класс области ставится по `focusin` и снимается только при переходе в другую область).

## Итоги проб (2026-11-10)

Пробы сделаны в конце работы, одной живой сессией вместе с проверкой клавиш (пользователь попросил не трогать Орку, пока в ней работают агенты). Орка 1.4.253, Electron 43.8.6.

1. **Клавиши доходят до фрейма панели — да** (пользователь: цифры, буквы, `/`, `.`, `?`, стрелки, русская раскладка). Один раз вместо `Shift+F` пришло `Ctrl+F` (полоса пробы: `ControlLeft`, `KeyF` без Shift) — это ввод, а не Орка; `Shift+F` проверен в headless.
2. **После `0` (`editor.open`) вкладка получает клавиши без клика — нет.** Вкладка выходит вперёд (`diff.focus` → `{ ok: true }`), фокус клавиатуры остаётся в панели.
3. **Панель может забрать фокус сама — нет.** `orca plugin dev request local.git-log probe.focus` → панель вызывала `viewport.focus()` (и `window.focus()` перед ним): `activeElement` внутри фрейма менялся, `document.hasFocus()` оставался `false` сразу и через 300 мс; окно Орки активно (`hyprctl activewindow`). Перепроверено свежим агентом: html-панель Орки — отдельный Electron `<webview>`, в коде Орки нет ничего, что переводит на него фокус по просьбе гостя, а в host API 1.4 нет вызова фокуса (`editor.open` — только `{ workspaceId, path }`, `commands.run` — переключатели сайдбаров и т. п.). Поэтому `1`–`4` во вкладке не назначены, а в подсказке `?` под клавишами вкладки написано, что фокус между панелью и вкладкой переходит кликом. Чтобы это стало возможным, нужен вызов фокуса в API Орки (issue апстриму).
4. **Линия области остаётся, когда фокус ушёл из панели — да** (класс по `focusin`).

## После живой проверки (2026-11-10)

- Esc в окне фильтра — в список коммитов; стрелки в окнах фильтров; `Shift+буква` — сброс фильтра (см. «Клавиши» и «Поведение»).
- «Описание»: ↑/↓ переходят между строками коммитов, Enter или пробел раскрывают строку; за первой и последней строкой стрелка прокручивает, как раньше, чтобы длинное сообщение можно было дочитать.
- Refresh (`r` и кнопка) пишет «Обновлено.» в баннер: без этого обновление, не нашедшее нового, ничего не меняет на экране.
- Пока открыто меню, окно фильтра или диалог, клавиши панели не работают, даже если фокус упал на `body` (финальное ревью).
- Если строка дерева с фокусом исчезла (её папку свернули, например `c`), фокус встаёт на её папку (`mountTree`, финальное ревью).
