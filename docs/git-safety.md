# Git safety

Every git command the worker (`src/worker/`) runs, where its inputs come from, how they are checked, what happens when it fails, and which test covers it. The plugin runs git on its users' repositories: nothing it does may damage a repository or lose work. Checked against git 2.56.0 on 2026-11-10.

## Rules every call follows

- git starts only through `createGit` (`src/worker/git.ts`): `execFile`, never a shell, with `-c core.quotepath=off -c color.ui=false -c log.showSignature=false` in front, `GIT_TERMINAL_PROMPT=0` (never asks for a password) and `LC_ALL=C`, a 60 s timeout (120 s for rebase, merge, cherry-pick, revert and fetch). The only shell git itself starts is the interactive rebase's sequence editor and `exec` lines, with every word single-quoted (`shQuote`).
- A request names its repository by `root`. The worker accepts only a path that is the top level of its own repository (`gitFor` in `main.ts`).
- No value from a frame ever becomes a git option. Commit hashes must match `^[0-9a-f]{40}$`. Branch and tag names go through `assertName` (`actions.ts`): trimmed, not empty, not starting with `-`, no `@{`, not under `refs/`, and accepted unchanged by `git check-ref-format --branch` (tags: `git check-ref-format refs/tags/<name>`). A branch to merge or rebase onto is sent as its full ref (`refs/heads/…` or `refs/remotes/…`, never a short name, which can mean another ref: `heads/x` is branch `x`, `tags/x` tag `x`, and a tag wins over a branch of the same name); the ref must exist exactly (`git show-ref --verify --quiet <ref>`) and name a commit (`git rev-parse --verify -q --end-of-options <ref>^{commit}`). File paths come after `--` as `:(literal)<path>`.
- Actions on the current branch carry the HEAD the confirmation showed (`expectHead`); the worker runs them only while HEAD is still there, and makes the backup the user asked for first (`runGuarded` in `backup.ts`). Undo is bound to the HEAD the action left.
- While a rebase, merge, cherry-pick or revert is stopped (started in a terminal, say), every action that moves HEAD or touches the index or the files is refused. "Stopped" is what `git status` reports: `rebase-merge`, `rebase-apply`, `MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD` or a `sequencer` todo list in the git dir (`operationInProgress` in `rebase.ts`). Creating a branch without checkout or a tag only adds a ref and stays allowed.
- Rewrites, merge and rebase onto run with `--autostash`. When they fail they are aborted, which re-applies the stash; when they succeed but the stash does not apply cleanly, the banner says the changes are in the stash and offers no Undo.

Test names below are from `src/worker/safety.test.ts` unless a file is named; `git.test.ts`, `branchActions.test.ts`, `backup.test.ts`, `main.test.ts` and `selection.test.ts` sit next to it.

## Coverage by case

| Operation | Normal input | Hostile input refused | Failure aborted, nothing changed | Local changes kept | Pushed commits reported | Operation in progress refused |
|---|---|---|---|---|---|---|
| Checkout (branch, hash, remote branch) | yes | yes | yes | yes | not a rewrite | yes |
| New branch / new tag | `git.test.ts` | yes (incl. `refs/`) | yes | yes | not a rewrite | with checkout: yes; without, and tags: allowed |
| Cherry-pick, revert | `git.test.ts` | yes | yes (conflict on first/second commit, refused first commit) | yes | not a rewrite | yes |
| Reset soft / mixed / keep | yes | yes | yes | yes | no warning (see limits) | yes |
| Reset hard | `git.test.ts` | yes | yes | discards by design | no warning (see limits) | yes |
| Undo commit | `git.test.ts` | yes | nothing to abort (`reset --soft`) | yes | yes | yes |
| Squash, fixup, drop, reword, interactive rebase | `git.test.ts` | yes | yes (conflict, hook, refused message) | yes, with a warning when they do not re-apply | yes | yes |
| Create patch | `git.test.ts` | paths: yes; hashes: `git.test.ts` | yes (existing file) | yes | not a rewrite | not needed (reads only) |
| Rename, delete (`-d` / `-D`) | `branchActions.test.ts` | yes | yes | yes | not a rewrite | git refuses the rebased branch |
| Merge, rebase onto | `branchActions.test.ts` | yes (short names meaning another ref) and `branchActions.test.ts` | yes (conflict, hooks, untracked file; merge also unrelated histories and no committer identity) | yes | rebase onto: yes | yes |
| Fetch | `branchActions.test.ts` | no input | `branchActions.test.ts` | yes | not a rewrite | allowed (remote refs only) |
| Backup, restore to backup, delete backup | `backup.test.ts` | `backup.test.ts` | `backup.test.ts` | yes | restore is a reset | restore: yes; delete: git refuses the rebased branch |
| Undo after an action | yes | `backup.test.ts` (moved HEAD) | yes | yes | — | yes |

## Known limits

- Reset --hard discards local changes and overwrites untracked files the target commit tracks; the dialog confirms it and offers a stash backup of tracked changes (untracked files are not saved). Task 15's last round is adding a warning for those untracked files; it is not covered here.
- Reset (and restore to a backup) moves the branch away from commits a remote branch already holds without a pushed warning; the commits stay on the remote.
- Pushed means "a remote-tracking branch holds it": a push from another machine that was not fetched is not seen.
- A bisect in progress is not treated as an operation in progress.
- A checkout target that looks like an abbreviated hash but is no branch name is resolved by git as a commit and checked out detached.
- The patch path is checked, then written: a link created in between is not caught.
- A `MERGE_AUTOSTASH` that an earlier merge in a terminal left behind is not looked for before a merge.
